01/Challenge Description

Challenge Description

MP3로 압축된 진짜 목소리를,
진짜라고 판단할 수 있을까요?

부분 음성 딥페이크는 앞뒤의 진짜 목소리는 그대로 두고, 특정 구간만 딥페이크로 바꾼 음성입니다. “계좌는 110-482-937261입니다”라는 말에서 계좌번호만 다른 번호로 바꿔 넣는 식입니다. 문장 대부분이 진짜라서, 듣는 사람은 어디가 바뀌었는지 알아채기 어렵습니다.

탐지기는 ‘경계’를 봅니다

부분 딥페이크는 진짜 음성 사이에 합성 구간을 이어 붙여 만듭니다. 이어 붙인 자리에는 에너지·스펙트럼·위상이 갑자기 바뀌는 불연속이 남고, 탐지기는 이것을 가장 강한 단서로 씁니다. Baseline인 BAM은 아예 이 경계를 찾도록 설계된 모델입니다.

통화는 경계를 지우고, 새 경계를 만듭니다

통화 음성은 20ms 정도의 짧은 조각(프레임)으로 잘려 압축된 뒤 전송됩니다. 이때 조각 몇 개가 중간에 사라지기도 하는데, 받는 쪽은 그 자리를 바로 앞 소리로 대충 메웁니다. 사라진 조각이 마침 진짜와 딥페이크가 만나는 경계였다면, 경계가 통째로 사라집니다.

그래서 탐지기에는 두 가지 문제가 생깁니다.

① 가짜를 놓칩니다

압축으로 경계가 뭉개지거나 사라지면, 탐지기가 볼 단서가 없어집니다.

② 진짜를 가짜로 봅니다

압축과 메운 자국이 진짜 음성에도 작은 끊김을 남깁니다. 탐지기는 이것을 조작 흔적으로 착각합니다.

  1. 계획

    처음에는 통화·압축 환경에서도 이런 조작을 찾아내는 연구를 계획했습니다.

  2. 질문

    교수님은 일반화 문제를 짚으셨습니다.

    특정 환경에서 잘 작동하더라도, 코덱이 바뀌면 성능이 달라질 수 있다.
  3. 실험

    그래서 PartialSpoof 데이터셋에서 고른 같은 음성을 Clean·Opus·AAC·MP3 네 조건으로 만들고, 기존 탐지 모델 BAM과 MultiResoModel-Simple로 평가했습니다.

  4. 발견

    결과는 예상과 달랐습니다. 압축된 딥페이크 음성은 대부분 가짜로 찾아냈지만, 결과를 나눠 보니 진짜 음성까지 가짜로 판단한 경우가 매우 많았습니다. MP3에서 가장 심했고, Opus에서도 진짜 음성의 20.1~36.8%를 가짜로 불렀습니다. 가짜를 잘 찾는 대신, 정상적인 목소리까지 의심하고 있었던 것입니다.

    MP3 · 가짜를 가짜로 찾아낸 비율98.5~99.8%
    MP3 · 진짜를 가짜로 판단한 비율67.4~78.0%

    Baseline 두 종(BAM·MultiResoModel-Simple). 모델마다 Clean Dev에서 정한 임계값을 그대로 쓰고, Eval 17,809발화(정상 1,839 · 가짜 15,970)로 측정했습니다.

  5. 초점

    그래서 이 챌린지의 초점을 MP3 압축 환경에서 진짜 음성을 진짜로 판단하는 비율을 높이는 것으로 정했습니다. BAM과 MultiResoModel-Simple을 기준 모델로 삼아, 딥페이크 탐지 능력은 지키면서 진짜 음성에 대한 오탐을 줄이는 방법을 비교합니다.

가짜는 놓치지 않고,
진짜 목소리는 진짜로 인정하는 것.이것이 저희 챌린지가 풀려는 문제입니다.

02/Task Definition

Task Definition

음성 압축으로 생긴 변화를 조작의 흔적으로 오인하지 않도록, 진짜 음성의 오탐은 줄이고 부분 딥페이크 탐지 성능은 유지하는 것이 목표입니다.

TASK 1

압축된 진짜 음성의 오탐 감소

진짜 음성이 Opus·AAC·MP3로 압축된 뒤에도 진짜로 판정되도록 탐지 모델을 개선합니다. 압축 흔적 때문에 가짜로 잘못 판단하는 비율을 낮추는 데 중점을 둡니다.

TASK 2

부분 딥페이크 탐지 성능 유지

진짜 음성의 오탐을 줄이는 과정에서 부분 조작 음성까지 진짜로 통과시키지 않아야 합니다. 동일 발화의 Clean·Opus·AAC·MP3 버전에서 기존 모델과 개선 모델을 비교해, 진짜 음성의 판별이 개선되면서 가짜 음성의 탐지 성능도 유지되는지 평가합니다.

Baseline & Proposed Method

Proposed Method

압축된 진짜 음성을 가짜로 오인하는 문제를 줄이기 위해, 기존 연구를 참고한 세 가지 개선 방법을 비교합니다.

  • 압축 음성 함께 학습하기 — 원본과 압축 음성을 함께 보여주어, 압축된 소리에도 익숙해지도록 합니다.
  • 원본과 압축본의 특징 맞추기 — 같은 음성은 압축 여부와 관계없이 비슷한 특징을 갖도록 학습합니다.
  • 구간 내부의 단서도 활용하기 — 진짜와 가짜가 만나는 경계뿐 아니라, 구간 안의 특징도 학습해 가짜 탐지 성능을 유지하고자 합니다.

각 방법을 BAM과 MultiResoModel-Simple에 적용해 비교할 계획입니다. 학습에는 Clean과 Opus만 사용하고, 학습에서 제외한 AAC·MP3에서도 효과가 있는지 평가합니다.

적용 방식MultiReso 기반BAM 기반
+ 압축 음성 함께 학습Ours1Ours4
+ 원본·압축본 특징 맞추기Ours2Ours5
+ 구간 내부 단서 학습Ours3Ours6

현재는 실험 계획이며, 검증한 결과를 리더보드에 반영할 예정입니다.

05/Evaluation Setup

Evaluation Setup

기준 모델과 제안 모델을 동일한 데이터와 채점 규약으로 비교합니다. 같은 Eval 17,809발화(정상 1,839 · 가짜 15,970)를 네 조건으로 평가합니다. 부분 조작 음성을 대상으로 하되, 평가는 조작 위치가 아니라 발화에 조작이 포함됐는지를 측정합니다.

평가 조건은 Clean·Opus 32kbps·AAC-LC 64kbps·MP3 64kbps입니다. 모두 16kHz 모노 WAV로 읽으며, 패킷 손실은 적용하지 않습니다.

같은 Eval 발화를 Clean·Opus·AAC·MP3 네 조건으로 평가하고, 각 조건의 EER·FNR·FPR과 추가 분석 지표를 산출합니다.

평가 절차와 판정 기준

01입력 통일

모든 모델은 16kHz 음성을 2초 window로 나눠 전체 발화를 처리합니다. 같은 발화·코덱에는 같은 입력 window를 사용합니다.

마지막 구간이 2초보다 짧으면
마지막 window를 앞쪽과 겹쳐 발화 끝까지 처리합니다.
발화 전체가 2초보다 짧으면
오른쪽에 0을 채워 2초로 맞춥니다.

02발화 점수 계산

모델 출력을 점수가 높을수록 가짜가 되도록 맞춥니다. 여러 window의 점수 중 최댓값을 발화 점수로 사용합니다.

모델별 변환 규칙은 Eval 평가 전에 고정합니다. 제안 모델에도 같은 점수 방향과 최댓값 집계 규칙을 적용합니다.

기준 모델의 점수 변환

MultiResoModel-Simple: 각 window의 spoof 출력
BAM: 각 window에서 genuine 프레임 logit의 최솟값에 음수를 취한 값

03EER 계산

조건별 점수로 ROC를 만들고, FPR = FNR 교차점을 선형 보간해 EER을 구합니다.

Eval ROC는 EER 계산에만 사용하며, 실제 분류 임계값을 Eval에서 조정하지 않습니다.

04고정 임계값으로 판정

모델별로 Clean Dev에서 임계값 하나를 선택하고, 모든 Eval 코덱에 그대로 적용합니다.

score >= threshold이면 가짜로 판정합니다.

임계값 선택 규칙

Clean Dev의 유한한 실제 ROC 임계값 중 FPR·FNR 차이가 가장 작은 값을 선택합니다. 동점이면 FPR이 낮은 지점을 우선합니다.

EER과 고정 임계값 지표는 구분합니다. FP·FN·FPR·FNR은 위에서 고정한 임계값으로 계산하므로 EER 지점의 값과 다를 수 있습니다. EER·FNR·FPR은 %, FP·FN은 개수로 보고합니다.

공정한 비교와 재현

Train → Dev → Eval
기준 모델은 공개 체크포인트를 사용합니다. 제안 모델은 Train으로 학습하고 설정·체크포인트·임계값은 Dev에서 선택합니다. 모든 설정을 고정한 뒤 Eval로 최종 평가합니다.
정답은 채점에만 사용
정답 라벨은 지표 계산에 사용하며 모델 추론 입력으로 제공하지 않습니다. 사전학습 모델과 체크포인트의 출처·파일명·해시를 기록합니다.
같은 표본으로 전체 비교
모든 모델이 같은 Eval ID·라벨과 네 코덱 조건의 점수 계산을 완료한 뒤 비교합니다. 소량 테스트 결과를 전체 성능으로 제시하지 않습니다.
점수 저장으로 재분석
데이터·가중치·코드·실행 환경·발화별 점수를 기록하고, 입력 파형과 공통 window의 해시를 모델 간 대조합니다. 저장된 점수로 재추론 없이 지표를 다시 계산할 수 있습니다.

상세 정의는 평가 규약과 전체 평가 결과 CSV에서 확인할 수 있습니다.

06/Leaderboard

Leaderboard

MP3 압축 후에도 진짜와 가짜를 고르게 구분하는 성능을 비교합니다. 순위는 MP3 조건의 균형 정확도가 높은 순서로 정하며, 진짜 인정률·탐지율·EER도 함께 공개합니다.

진짜 인정률은 정상 음성을 정상으로 판정한 비율(100% − FPR), 탐지율은 가짜 음성을 가짜로 판정한 비율(100% − FNR)입니다. 균형 정확도는 두 비율의 평균, 즉 (진짜 인정률 + 탐지율) ÷ 2입니다. 세 지표는 모두 Clean Dev에서 정한 고정 임계값으로 계산합니다. EER은 별도로 산출하며 순위에는 반영하지 않습니다.
