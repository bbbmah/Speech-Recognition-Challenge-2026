01 · DESCRIPTION

Challenge Description

콜센터 상담, 은행 ARS, 예약 시스템처럼 음성인식이 실제로 쓰이는 곳에서 가장 중요한 정보는 숫자입니다. 그런데 한국어 숫자 발화는 음성인식에 특히 까다롭습니다. 같은 숫자도 한자어(삼, 십오)와 고유어(세, 열다섯)로 읽히고, 전화번호는 자릿수 단위(공일공)로, 금액은 만·억 단위(삼만 오천)로 읽힙니다. 6월과 10월은 유월, 시월처럼 불규칙하게 읽습니다.

기존 벤치마크는 CER(문자 오류율)로 평가하기 때문에, 계좌번호 한 자리가 틀려도 거의 감점되지 않습니다. 하지만 실제로는 송금이 실패하는 치명적인 오류입니다. K-NumASR은 숫자가 포함된 한국어 발화만 모은 평가 세트와 숫자 단위의 엄격한 지표로 이 문제를 측정합니다.

목표 · 숫자가 포함된 한국어 음성을 입력받아, 숫자를 아라비아 숫자로 정확히 표기한 전사문을 출력하는 시스템을 만들고 NEM으로 비교합니다.

같은 음성, 세 가지 출력

음성: “계좌번호는 삼삼공일 이이 오칠팔구예요” · 정답: 3301-22-5789

모델 A
3301-22-5789
CER 0% · NEM 정답
모델 B
3301-22-5781
한 자리 오류 · NEM 오답
모델 C
삼삼공일 이이 오칠팔구
소리는 맞음 · 표기 실패

모델 B는 CER로는 거의 만점이지만 실제로는 실패입니다. 모델 C는 잘못 들은 것이 아니라 숫자 표기 변환(ITN)에 실패한 경우로, K-NumASR은 두 경우를 구분해서 진단합니다.

03 · METHOD

Baseline & Proposed Method

Baseline

Whisper Baseline

OpenAI Whisper tiny, base, small, medium, large-v3-turbo, large-v3. 언어를 ko로 고정한 그대로의 출력입니다. 모델 크기에 따른 숫자 인식 성능 변화를 봅니다.

wav2vec2 XLS-R Baseline

한국어로 파인튜닝된 CTC 모델(kresnik/wav2vec2-large-xlsr-korean). 숫자를 한글 발음형으로 출력하는 대표적인 비교군입니다.

Proposed

K-ITN Proposed

한국어 숫자 표현을 아라비아 숫자로 바꾸는 규칙 기반 후처리입니다. 한자어(삼만 오천 원 → 35000원), 고유어(스물세 살 → 23살), 자릿수 읽기(공일공 → 010), 혼합 표기(3만 5천 → 35000), 유월·시월을 처리하고, 이분·이번처럼 숫자로 오인되기 쉬운 단어는 예외 처리합니다.

NumPrompt Proposed

Whisper의 prompt_ids에 숫자 표기 예시 문장(전화번호, 계좌, 금액, 날짜)을 넣어, 추가 학습 없이 디코더가 쓰기형 숫자를 출력하도록 유도합니다.

NumPrompt + K-ITN Proposed

디코딩 단계의 유도와 후처리 단계의 보정을 결합합니다. 모든 Baseline에도 K-ITN을 적용한 결과를 함께 보고해 후처리 효과를 분리합니다.

K-Num Synthetic 유형

전화번호phone

휴대전화, 지역번호, 대표번호를 자릿수 단위로 읽습니다. 0은 '공'으로 읽습니다.

발음수빈 씨 번호가 공일공 오팔팔일 삼구구팔 맞나요?
정답수빈 씨 번호가 010-5881-3998 맞나요?
계좌번호account

3-2-6, 4-3-6 등 은행별 형식의 긴 자릿수 열입니다. 한 자리 오류도 송금 실패로 이어집니다.

발음받는 분 계좌는 국민은행 공칠오사 칠삼오 사팔육사삼구, 예금주는 지영입니다.
정답받는 분 계좌는 국민은행 0754-735-486439, 예금주는 지영입니다.
금액amount

백 원부터 억 단위까지의 금액입니다. 만·억 단위 한자어 수사와 쉼표 표기가 필요합니다.

발음이번 달 관리비는 사천칠백 원이 나왔어요.
정답이번 달 관리비는 4,700원이 나왔어요.
날짜·시간datetime

유월·시월 같은 불규칙 읽기, 고유어 '시'와 한자어 '분'이 섞인 시각을 포함합니다.

발음예약 시간은 오전 아홉 시 사십오 분입니다.
정답예약 시간은 오전 9시 45분입니다.
고유어 수량native

스물세 살, 열다섯 개처럼 고유어 수사와 단위 명사가 결합된 표현입니다.

발음상자 일곱 개 주세요.
정답상자 7개 주세요.

정답은 쓰기형, TTS 입력은 코드로 생성한 발음형입니다. 발음을 직접 통제하기 때문에 TTS가 숫자를 임의로 읽어 정답과 어긋나는 문제를 막습니다. 모든 문장은 seed=2026으로 재현됩니다. 모든 음성은 16 kHz mono FLAC으로 저장했습니다.

Key Findings

CER로는 보이지 않는 오류

whisper-large-v3는 CER 7.4%로 낮지만 NEM은 64.7%입니다. 숫자가 들어간 발화 3개 중 1개 이상에서 숫자를 정확히 받아쓰지 못했습니다.

큰 모델이 항상 낫지는 않다

그대로의 출력에서는 whisper-medium(NEM 72.9)이 large-v3(64.7)보다 높습니다. large 계열은 금액을 6,700만 원처럼 혼합 표기로 쓰는 경향이 강해 금액 NEM이 28.3%에 그쳤습니다.

K-ITN의 효과

K-ITN 적용 후 large-v3의 금액 NEM은 28.3% → 96.7%, 발음형으로 출력하는 wav2vec2는 전체 NEM 0.0% → 36.5%로 올랐습니다.

NumPrompt의 효과

추가 학습 없이 프롬프트만으로 large-v3-turbo의 NEM이 67.7% → 71.6%로 올랐고, K-ITN과 결합한 시스템이 84.9%로 1위입니다.

가장 어려운 유형: 자릿수 읽기

전화번호와 계좌번호는 최고 성능도 각각 78.3%, 76.7%입니다. 자릿수 누락·치환(예: 5881 → 588) 같은 인식 오류라 후처리로는 고칠 수 없으며, 향후 과제로 남습니다.

평가 데이터 표기의 한계

FLEURS 정답에는 4만 명처럼 혼합 표기가 섞여 있어, K-ITN이 이를 40000으로 바꾸면 NEM에서 오답이 됩니다. 이런 표기 차이는 NEM-norm에서 정답과 예측을 함께 정규화해 따로 진단합니다.
