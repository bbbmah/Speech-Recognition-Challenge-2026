Cascade vs Direct

한국어 음성 명령 의도 인식에서 Cascade와 Direct 방식 비교

"내일 아침 7시에 알람 맞춰줘"라는 명령을 처리할 때 시스템에 필요한 것은 문장 전체가 아니라 의도(alarm_set)입니다. 본 챌린지는 한국어 스마트 스피커 명령 60종을 대상으로, 음성을 텍스트로 전사한 뒤 의도를 분류하는 Cascade 방식과 전사 없이 오디오에서 바로 분류하는 Direct 방식을 동일한 평가 조건에서 비교합니다.

01 / Challenge Description

Challenge 개요

텍스트 전사는 회의록이나 검색처럼 기록이 필요한 작업에는 필수지만, 알람 설정이나 조명 제어처럼 정해진 선택지 중 하나를 고르는 작업에는 꼭 필요하지 않을 수 있습니다. 최근 발표된 Audio Decision Model(Jev 계열)과 Audio Action Model(Thud)은 전사를 생략해 속도를 크게 높였다고 보고했지만, 정확도와 확률 보정까지 같은 조건에서 비교한 결과는 아직 부족합니다. 본 챌린지는 다음 세 가지를 확인합니다.

  1. 정확도전사 없이 분류하는 Direct 방식은 Cascade 방식과 비교해 한국어 명령에서 정확도가 얼마나 차이 나는가
  2. 속도자기회귀 디코딩을 생략했을 때 같은 GPU에서 발화당 처리 시간은 얼마나 줄어드는가
  3. 신뢰도각 방식이 출력한 확률이 실제 정답률과 얼마나 일치하는가 (ECE). 확률이 낮을 때 실행을 보류하는 정책에 쓸 수 있는 수준인가

관련 연구

음성 의도 인식(Spoken Language Understanding, SLU)은 ASR과 텍스트 분류를 잇는 pipeline 방식과, 음성에서 바로 의도를 예측하는 end-to-end 방식으로 나뉘어 연구되어 왔습니다.

Dataset

SLURP → MASSIVE → Speech-MASSIVE

영어 음성 명령 데이터셋 SLURP의 60개 intent 체계를 50여 개 언어 텍스트로 번역한 것이 MASSIVE이고, 이 중 한국어를 포함한 12개 언어를 실제 사람 목소리로 녹음한 것이 Speech-MASSIVE(Interspeech 2024)입니다.

Cascade

ASR + NLU pipeline

Whisper 등 ASR 모델의 전사 결과를 텍스트 분류기에 입력하는 방식입니다. 텍스트 학습 데이터를 충분히 활용할 수 있지만, ASR 오류가 분류 단계로 전파되고 디코딩에 시간이 듭니다.

Direct

End-to-end SLU · SSL encoder

wav2vec 2.0, HuBERT, Whisper 인코더 등 음성 표현 위에 분류 헤드를 학습하는 방식으로, SUPERB 벤치마크의 intent classification이 대표적입니다. 디코딩이 없어 빠르지만 의도가 라벨링된 음성 데이터가 필요합니다.

Audio Decision

Jev · Qwen-Audio-Jev · Thud (2026)

전사 대신 선택형(Choice), 점수형(Score), 예/아니오형 결정을 오디오에서 직접 출력하는 모델들입니다. Qwen-Audio-Jev는 기존 모델 대비 약 20배 빠른 추론을 보고했으나, 확률 보정과 다른 방식과의 동일 조건 비교는 제한적입니다.

02 / Pipeline

한국어 음성 명령 1개를 입력받아 60개 intent 중 하나와 클래스별 확률을 출력합니다. 시스템은 중간에 텍스트 전사를 거치는지에 따라 두 트랙으로 나뉩니다.

weather_query
TRACK A · CASCADE

Transcribe → Decide

중간에 텍스트 전사를 생성하고, 그 텍스트로 의도를 판단합니다. 텍스트 전용 데이터(MASSIVE ko-KR train)를 분류기 학습에 사용할 수 있습니다.

TRACK B · DIRECT

Decide without transcript

추론 과정에서 텍스트를 생성하지 않고 오디오 표현에서 바로 의도를 분류합니다. 학습용 음성은 제공된 오디오 학습 분할만 사용합니다.

공통 규칙

평가셋 음성과 그 정답 텍스트는 학습·모델 선택에 사용할 수 없습니다. 지연시간은 동일 GPU(Colab T4)에서 batch 1, fp16으로 특징 추출부터 최종 확률까지의 end-to-end 시간을 측정합니다.

03 / Baseline & Method

베이스라인과 제안 방법

공개된 사전학습 모델로 4개의 베이스라인 시스템을 구성했습니다. 학습과 추론 코드는 개인 GitHub 레포의 baseline/ 폴더에 있습니다.

Baseline systems

REFERENCE

Oracle text → KLUE-RoBERTa

정답 텍스트를 분류기에 그대로 넣은 결과입니다. ASR 오류가 없을 때 Cascade 방식이 낼 수 있는 상한선을 보여주며, 순위에는 포함하지 않습니다.

cascade.py --oracle
CASCADE

Whisper-small → KLUE-RoBERTa

Whisper-small(244M)로 한국어 전사(greedy) 후, MASSIVE ko-KR 텍스트로 fine-tuning한 KLUE-RoBERTa-base로 분류합니다.

cascade.py --asr openai/whisper-small
CASCADE

Whisper-large-v3-turbo → KLUE-RoBERTa

더 강한 ASR로 교체했을 때 정확도는 얼마나 오르고 지연시간은 얼마나 늘어나는지 확인합니다.

cascade.py --asr openai/whisper-large-v3-turbo
DIRECT

Whisper-small encoder + attentive pooling

Whisper-small의 인코더만 가중치를 고정해 사용하고 디코더는 쓰지 않습니다. 인코더 출력에 attentive pooling과 MLP 분류 헤드를 붙여 학습합니다. Whisper-small Cascade와 같은 인코더를 쓰므로 디코딩 유무에 따른 차이를 비교할 수 있습니다.

Plan 1

텍스트 → 음성 지식 증류

텍스트로 충분히 학습된 Cascade 분류기를 teacher로 두고, teacher의 출력 확률을 정답 삼아 Direct 모델을 학습합니다. 부족한 음성 데이터를 텍스트 쪽 지식으로 보완하는 것이 목표입니다.

Plan 2

확률 기반 하이브리드

Direct 모델의 확률이 충분히 높으면 바로 결정하고, 낮을 때만 Cascade로 넘깁니다. 정확도와 처리 시간 사이에서 두 방식 각각보다 나은 지점이 있는지 확인합니다.

Direct 학습 오디오가 더 적은 이유

Speech-MASSIVE 한국어는 train 분할의 음성이 녹음되지 않아, 텍스트는 1만 개 이상이지만 라벨링된 음성은 약 2천 개입니다. 텍스트 데이터는 많고 음성 데이터는 적은 상황은 실제 서비스를 만들 때도 흔하기 때문에, 이 조건을 그대로 유지한 채 두 방식을 비교합니다.

베이스라인 결과 요약

Cascade(Whisper-large-v3-turbo)는 정확도 85.3%로 정답 텍스트를 넣은 Oracle(87.9%)과 2.6%p 차이에 그쳐, 한국어 명령에서는 ASR 오류의 영향이 크지 않았습니다. Direct는 정확도가 66.3%로 19.0%p 낮았지만, 처리 시간은 39.9ms로 Cascade(245.0ms)보다 약 6배 짧았습니다. 확률 보정 오차(ECE)도 Direct가 0.073으로 가장 컸습니다.

Direct의 정확도 차이는 학습에 쓸 수 있는 음성이 1,338개뿐이라는 데이터 조건과 관련이 있다고 보고, 제안 방법(텍스트 지식 증류, 확률 기반 하이브리드)에서 이 차이를 줄이는 것을 목표로 합니다.
